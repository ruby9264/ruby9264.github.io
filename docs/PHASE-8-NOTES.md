## 1. §11 was missing entirely — now built

§11 asks for an Open Graph image, a favicon set, JSON-LD, `robots.txt` and
`sitemap.xml`. None existed before this phase.

All the images are **generated by `npm run assets`**
(`scripts/generate-assets.mjs`) rather than committed as binaries — the art
stays reviewable in a diff, and the moss/navy palette can't drift from
`tokens.css`. No image libraries: a PNG is a few CRC'd chunks around a zlib
stream, and Node ships zlib.

| File | Size |
|---|---|
| `favicon-16.png`, `favicon-32.png` | pixel `R` in a moss square |
| `apple-touch-icon.png` (180) | same mark |
| `icon-512.png` | same mark |
| `og-image.png` | 1200×630 — starfield, the `R // MOON STATION` wordmark in a hand-built 5×7 pixel font, MOCHI, and the station module |

Plus Open Graph and Twitter card meta, a `Person` + `CreativeWork` JSON-LD
graph, `robots.txt` and `sitemap.xml`.

**The email is deliberately absent from the JSON-LD.** §S10 requires the
address be obfuscated, and structured data is precisely what a harvester
parses — putting it there would undo the obfuscation everywhere else.

⚠ **The domain is a placeholder.** `canonical`, `og:url`, `og:image` and
`sitemap.xml` all use `https://r-moon-station.netlify.app/`. Set the real one
at deploy; Open Graph needs absolute URLs so this can't be left relative.

## 2. One real bug found and fixed: the S06 deck at 320px

Two faults, both only visible at narrow widths:

- **19px of horizontal overflow.** §S06 sets the peek cards at 4° and 8°. A
  rotated box has a wider bounding box than the box itself, and at 320px the
  8° card spanned −19 → 339 on a 320 viewport. Below 640px the angles now
  halve to 2° and 4°, which reads the same and fits. Deck now maxes at
  **319.9**.
- **Cards ran through the arrows.** The stack was `min-height: 420` with every
  card absolutely positioned, so the container never grew. At 320px the cards
  are ~600px tall, so they overlapped the arrows and dots below. The front
  card is now **in flow** and defines the container's height; only the two
  peeks are absolute. Stack height now tracks the card (599.5) and the arrows
  sit 48px clear.

### The 320px measurement that looked like a bug and wasn't

`documentElement.scrollWidth` reported 334 on a 320 viewport even after the
deck fix. It is **not** page overflow: hiding the nav, the dock and the
floating bot leaves it at 334, and it equals `innerWidth` exactly — this
pane's layout viewport includes a 14px classic-scrollbar gutter. On a real
device profile (`pointer: coarse`, overlay scrollbars) `innerWidth ===
clientWidth === 375` and `scrollWidth === clientWidth`: **no overflow**.

The one element still crossing the line is the S04 tab strip, which is
`overflow-x: auto` and scrolls — exactly what §S04 asks for at 320px.

## 5. Not done, and why

- **Lighthouse** — the CLI isn't available in this environment, so I have not
  run it and will not claim a score. The measurable inputs it grades (contrast,
  labels, landmarks, heading order, touch targets, meta, structured data,
  bundle size) are all verified above.
- **Cross-browser** — only Chromium is available here. §14 flags Safari's
  `clip-path` and `steps()` as the usual offenders, and both are load-bearing:
  the S00 flood and reveal use `clip-path`, and every animation uses `steps()`.
  **Worth a real Safari pass before launch.** The one place I pre-empted this
  is the pixel cursor, which is canvas-generated PNG rather than SVG precisely
  because Safari's SVG cursor support is unreliable.
- **Deploy** — out of scope for now, per your first message.
